# ВИНЛАНД: чеклист проверки MVP

Использовать после интеграции дизайна и кода. Отмечать результат и ссылку на найденную ошибку/исправление; наличие пункта в списке не означает, что проверка уже пройдена. Проверки без Telegram-токена выполняются на локальном демо и тестовой базе. Реальный Telegram, HTTPS-хост и push-уведомления проверяются только позднее на отдельном пользовательском этапе.

## Функциональные сценарии

- [ ] Первый запуск показывает пустой день, понятные действия и не создаёт ложных записей.
- [ ] «Сегодня»: планирование тренировки, отметка выполнения, отметка отдыха и смена результата согласованно обновляют экран и журнал.
- [ ] Повторный клик/повторный запрос не создаёт дубль дня и не меняет итог дважды.
- [ ] Ввод всех четырёх значений КБЖУ, сохранение, повторное открытие и правка отражаются в «Сегодня», деталях дня и недельной сводке.
- [ ] Пустое, отрицательное, нечисловое и чрезмерно большое значение получает понятную ошибку; уже заполненные поля остаются на месте.
- [ ] Журнал корректно показывает пустую историю, даты, статусы, детали дня и итог недели; дни без плана не считаются пропуском.
- [ ] Настройки напоминаний и часового пояса сохраняются после перезапуска; неверный ввод не сохраняется частично.
- [ ] Привязка к сайту обозначена как будущая функция, без активной синхронизации и фиктивных данных.

## Напоминания и время

- [ ] Нет плана, завершённый день, отдых и выключенные уведомления не создают отправку.
- [ ] Запланированный день без результата получает максимум два уведомления, второе примерно через 12 часов и только в те же локальные сутки.
- [ ] После отметки результата будущие напоминания для дня отменяются; смена настроек влияет только на будущие отправки.
- [ ] Проверены переход через полночь, смена недели, смена часового пояса и дни перехода на летнее/зимнее время для выбранного IANA-пояса.
- [ ] Повторный вызов планировщика не создаёт параллельной отправки одного слота; временный сбой обрабатывается повтором. Проверить и документировать допустимый повтор после аварии между ответом Telegram и фиксацией результата.

## Безопасность и сохранность

- [ ] Неверная/истёкшая подпись `initData` отвергается сервером; подмена `telegram_user_id` в запросе не открывает чужой журнал.
- [ ] Данные разных тестовых пользователей изолированы в «Сегодня», журнале и настройках.
- [ ] Демо-обход авторизации недоступен в production. Токены и данные пользователей не печатаются в логах и не попадают в Git.
- [ ] При ошибке БД интерфейс не объявляет действие сохранённым; после восстановления можно повторить без дубля.
- [ ] Резервная копия восстанавливается в отдельной тестовой базе и сохраняет дни/настройки.

## Интерфейс и выпуск

- [ ] Все состояния «Сегодня», «Журнал», «Детали дня», «КБЖУ» и «Настройки» пройдены кликами на узком экране и с открытой клавиатурой.
- [ ] Заголовочный шрифт корректно показывает кириллицу; основной текст читается без масштабирования; кнопки имеют текстовые названия и заметные состояния фокуса/нажатия.
- [ ] Нет тупиков: из ошибки, пустого состояния и формы ввода можно вернуться к «Сегодня» или повторить действие.
- [ ] `npm`-проверки проекта проходят на чистой установке; инструкция локального демо воспроизводится без настоящего Telegram-аккаунта.
- [ ] В финальном отчёте отдельно указано, что проверено локально, а что требует пользовательского токена и HTTPS-домена. Никакой статус «готово в Telegram» не ставится без такой проверки.

## Проверка перед Git и GitHub

- [ ] Просмотреть `git diff` и список новых файлов: в итог попали только проверенные изменения ВИНЛАНД и необходимые документы; старые материалы о записи клиентов и пользовательские `marketplace/` не затёрты.
- [ ] Проверить рабочее дерево и содержимое коммита на токены, `.env`, базы с личными данными, журналы и другие секреты. Настоящий токен пользователя не запрашивать и не читать.
- [ ] Убедиться, что изображения и другие бинарные файлы действительно нужны для бота, а не являются случайными артефактами демо.
- [ ] После финальных тестов зафиксировать согласованный результат в Git и отправить в GitHub для просмотра на ноутбуке; перед отправкой сверить удалённый репозиторий и ветку.
