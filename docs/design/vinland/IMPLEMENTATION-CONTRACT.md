# ВИНЛАНД — поля, состояния и переходы для разработки

**Статус:** дизайн-контракт для обсуждения. Он задаёт ожидаемое поведение интерфейса, а не утверждает архитектуру или API. Источник продукта: [SPEC.md](SPEC.md). Эта папка содержит автономный прототип; рабочий интерфейс Mini App находится в `public/`, серверные части — в `src/`. Совпадение реализации с этим контрактом нужно проверять отдельно.

## Модель дня

Ключ записи — календарная дата `YYYY-MM-DD` в выбранном пользователем часовом поясе IANA. Неделя начинается в понедельник. Даты хранятся как календарные ключи, а не как UTC-моменты: изменение часового пояса не переносит старые записи на другую дату.

```ts
type WorkoutStatus = 'unplanned' | 'planned' | 'completed' | 'rest';

type NutritionTotals = {
  kcal: number;      // целое число, 0 и выше
  proteinG: number;  // граммы, до 1 знака после запятой
  fatG: number;
  carbsG: number;
};

type DayEntry = {
  localDate: string;                  // YYYY-MM-DD
  workoutStatus: WorkoutStatus;
  nutrition: NutritionTotals | null; // null означает «не внесено», 0 — введённый ноль
  updatedAt: string;                  // момент сохранения в ISO 8601
};

type UserSettings = {
  timeZone: string;            // IANA, например Europe/Moscow
  remindersEnabled: boolean;
  firstReminderLocal: string;  // HH:mm; второе время = +12 часов
};
```

Для отсутствующего `DayEntry` интерфейс показывает `unplanned` и `nutrition: null`. Создавать пустые записи при просмотре дня не нужно. Данные тренировки и питания обновляются независимо, поэтому ошибка одного действия не стирает другое.

## Допустимые переходы

| Было | Действие | Стало | Уточнение |
| --- | --- | --- | --- |
| `unplanned` | Запланировать на сегодня | `planned` | Только для текущей локальной даты. |
| `unplanned` | Сегодня без тренировки | `rest` | Осознанное завершение дня. |
| `planned` | Выполнено | `completed` | После успешного сохранения закрыть напоминания на этот день. |
| `planned` | Сегодня без тренировки | `rest` | После успешного сохранения закрыть напоминания. |
| `completed` или `rest` | Изменить отметку | Выбор `completed` / `rest` / `planned` | Замена единственной отметки дня; интерфейс показывает текущий статус до сохранения нового. |
| Любое состояние | Сбросить отметку → подтвердить | `unplanned` | Явное действие; питание за день остаётся. |
| Любое состояние | Сохранить КБЖУ | Статус тренировки не меняется | Сохраняются все четыре числа атомарно. |

Повторные нажатия «Выполнено» и повторная доставка одного действия не должны создавать дублей. Для будущего/прошлого дня в текущем сценарии нет команд планирования; детали журнала только для чтения. Прототип даёт менять сегодняшнюю отметку после её сохранения.

## Проверка вводимых данных

| Поле | Правило | Ошибка в интерфейсе |
| --- | --- | --- |
| `kcal` | Обязательное конечное неотрицательное целое число. | «Введите калории целым числом от 0». |
| `proteinG`, `fatG`, `carbsG` | Обязательные конечные неотрицательные числа, максимум один знак после запятой. Точка и запятая как десятичный разделитель в UI. | «Введите число от 0, не более одного знака после запятой». |
| `timeZone` | Валидный идентификатор IANA. | «Выберите часовой пояс из списка». |
| `firstReminderLocal` | Время `HH:mm` в пределах 00:00–23:59. | «Укажите время первого напоминания». |

Практические верхние пределы значений КБЖУ, цели и единицы для международного рынка ещё не утверждены. UI не сравнивает введённые калории с суммой из БЖУ и не выдаёт медицинских или диетологических оценок.

## Напоминания

Триггер — день со статусом `planned` и включённые уведомления. Максимум два напоминания за этот день: в `firstReminderLocal` и через 12 часов по `timeZone`. Если одно время выпадает на следующие календарные сутки, не отправлять его как напоминание за прошлый день; это ещё одно основание подобрать первое время при настройке. После `completed`/`rest` в этот день не отправлять. Для реальной реализации нужны идемпотентный ключ отправки по пользователю, дате и порядковому номеру напоминания и правила обработки недоставки. Прототип лишь сохраняет настройки и показывает вычисленное время, не отправляет сообщения.

## Журнал и сводка

- Показывать неделю понедельник–воскресенье, переход на предыдущую и следующую доступную неделю.
- «Завершено» = число дней с `completed`; «Без тренировки» = число дней с `rest`; «КБЖУ внесены» = число дней с `nutrition != null`. `planned` не считается выполнением.
- День без записи показывать как «Нет записи», будущий день — как будущий, без редактирования.
- Детали выбранной даты показывают статус и точные четыре значения или «Не внесено».
- На текущий день из деталей есть «Открыть сегодня». Для прошедшего дня данные доступны только для чтения в этом черновике.

## Состояния сохранения и ошибки

| Ситуация | Поведение |
| --- | --- |
| Сохранение идёт | Кнопка блокируется, текст «Сохраняем…»; повторный запрос не создаётся. |
| Успех | Экран отражает новые данные; короткое «Сохранено» в статусной строке с `aria-live`. |
| Ошибка записи/сети | Старое сохранённое состояние остаётся; форма и введённые значения сохраняются; сообщение «Не удалось сохранить. Попробуйте ещё раз». |
| Ошибка поля | Фокус на первом неверном поле, текст ошибки рядом с ним; несвязанные значения сохраняются. |
| Устаревшее действие или повторный тап | Показать актуальное состояние и не дублировать запись. |
| Сброс отметки | Отдельное подтверждение «Сбросить отметку за сегодня?» с «Сбросить»/«Оставить». |

## Граница сайта и Telegram

В MVP нет данных сайта, объединённой истории, авторизации сайта и рабочего статуса подключения. Строка «Связь с сайтом появится позднее» информационная. Для будущего сценария потребуется отдельное согласование подтверждения Telegram-аккаунта на сайте, направления обмена и разрешения конфликтов, а также возможности отвязать аккаунт.

## Что является только поведением прототипа

Локальный HTML хранит демонстрационные записи в `localStorage` одного браузера. Он не содержит сервера, Telegram SDK, реальной отправки напоминаний, учётной записи и синхронизации. Встроенный режим имитации ошибки проверяет UX, но не доказывает надёжность будущей серверной записи.
